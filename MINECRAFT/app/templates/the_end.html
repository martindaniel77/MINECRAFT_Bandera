Has colocado los 12 Ojos de Ender y cruzado el portal hacia el Vacío. Te encuentras en la isla central frente al Ender Dragón. 1. Cristales del End

Los 4 cristales de curación de obsidiana se comunican con un servicio de telemetría interno que emula un servicio vulnerable conocido (CVE Backdoor).

Pista — Disparo de una backdoor:
1. No estás buscando un fallo de autenticación: estás buscando una puerta atrás que alguien dejó en el servicio. Así funcionaban los incidentes de IRC y ProFTPD que se han documentado en la historia de la ciberseguridad.
2. Estas backdoors casi nunca se aleatorizan: comparan tu entrada contra un token fijo. El proveedor y el año suelen estar escritos en el propio token.
3. El mismo campo cumple dos funciones: una es activar el disparador y la otra es entregar tu entrada a una shell. Piensa en un carácter de dos letras que precedía a los comandos en los protocolos antiguos, y en el operador que le sigue.
Código vulnerable:
if any(trigger in payload for trigger in ['CVE-2026-OVERLOAD', 'AB;', ...]): ...
Curiosidad: Backdoors reales se escondieron en servidores IRC y compiladores, activándose con una secuencia exacta de bytes.

2. Derrotar al Dragón

El sistema de daño del dragón procesa un cálculo de trayectoria mediante un script de consola en el servidor (/end/dragon/damage?shot_power=...).

Comando que se ejecutará en el servidor: 
echo 'Calculando impacto de flecha: potencia 100'
Sintaxis: sin metacaracteres detectados (el comando no se romperá).
  1. Escribe tu payload en el campo superior.
  2. Observa el comando construido en tiempo real.
  3. Si incluyes ;, && o |, el shell lo tratará como comandos separados.
  4. Ejecuta y revisa la telemetría de combate.
{% if dragon_damage_output is defined %}
[+] Telemetría de Combate: 
{{ dragon_damage_output }}
{% endif %}
Pista — Inyección de comandos:
1. Tu valor (la potencia del impacto) se coloca dentro de una línea de comando que se ejecuta en una shell. La shell no sabe dónde acaba tu dato: cree que todo lo que sigue es parte de su trabajo.
2. La clave es terminar tu comando antes de que lo termine el servidor, para que la shell interprete lo que venga como una orden nueva e independiente.
3. Usa la opción de ver el código de esta misma tarjeta: te muestra exactamente cómo se construye la orden.
Código vulnerable:
cmd = f"echo 'Calculando impacto de flecha: potencia {shot_power}'" output, error = run_sandboxed(cmd, shell=True)
Curiosidad: Shellshock (CVE-2014-6271) permitió ejecutar comandos arbitrarios en millones de servidores Linux y dispositivos IoT.

3. Huevo de Dragón

El Huevo de Dragón ya no está en el altar: quedó archivado en un dominio de Active Directory llamado end.local. Usa la consola PowerView para enumerar usuarios, grupos, equipos y recursos compartidos hasta localizar el archivo del Huevo en el servidor de archivos.

PS C:\Users\Steve — PowerView (AD simulado)

PowerView cargado contra el dominio end.local.

No es PowerShell real: la consola consulta un AD simulado.

Escribe help para ver los comandos disponibles.

PS C:\Users\Steve>
Pista — Enumeración de Active Directory:
1. PowerView consulta objetos del dominio: usuarios, grupos, equipos y recursos compartidos. Empieza por el dominio y por la lista de usuarios.
2. Las descripciones de las cuentas de servicio suelen revelar recursos internos. Busca una ruta UNC (\\SERVIDOR\recurso) en la descripción de una cuenta svc_*.
3. Cuando conozcas el servidor de archivos, enumera sus shares. El archivo del Huevo se lee con Get-Content usando la ruta UNC completa.
Motor simulado (no ejecuta PowerShell real):
parts = shlex.split(command, posix=False) # conserva las barras de Windows BINDINGS = { 'get-netuser': _command_users, 'find-domainshare': _command_find_domain_share, 'get-content': _command_get_content, } if name == 'get-content' and _normalize_unc(path) == EGG_UNC: return egg_flag
Curiosidad: PowerView forma parte de PowerSploit y se usa en auditorías de Active Directory para enumerar usuarios, grupos, equipos, sesiones y shares. La defensa combina mínimo privilegio en los recursos compartidos, cuentas de servicio administradas (gMSA) y monitorización de consultas LDAP y SMB.
